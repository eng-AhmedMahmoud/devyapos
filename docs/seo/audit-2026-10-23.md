# SEO and Core Web Vitals audit, 2026-10-23

The second pass, a day after [the first](audit-2026-10-22.md). Baseline:
Lighthouse 13.5.0, mobile (its default emulation and simulated throttling),
on all 26 indexed pages of https://pos.movingsystems.tech as deployed from
origin/main 9a8665e, plus a scripted read of every page's head (titles,
descriptions, canonical, hreflang, Open Graph and X cards, JSON-LD types, h1
count, heading order, image alt, robots) and of the sitemap and robots.txt.
Fixed on branch `feat/seo-overhaul`.

## What was already right

Every item the first audit fixed held in production: a unique title (30-65
characters) and description (70-160) per page in each language, absolute
self-canonicals, ar/en/x-default hreflang (x-default on Arabic, the default
locale) in the head and the sitemap, a sitemap of the 26 indexed URLs with
hand-dated lastmod, robots.txt naming it, `noindex, follow` on /terms and
/refund only, Organization + WebSite on every page, SoftwareApplication with
the EGP AggregateOffer where prices are shown, BreadcrumbList, FAQPage where
a page has its own questions, exactly one h1 per page, no skipped heading
level, alt on every image. Lighthouse SEO was 100 on all 26 pages.

There are no app, sign-in or dashboard routes on this host (the product runs
elsewhere), so the noindex list stays /terms and /refund; the API is
covered below.

## Fixed

- [x] **LCP text was transparent when it painted.** Chrome does not count an
  element at opacity 0. Two parts of the motion layer kept the largest text
  there:
  - The hero entrance (`.reveal-now`) faded from 0, so LCP landed at the end
    of the fade. It now rises on the transform only. On the local build with
    devtools throttling, LCP went from 2.8-2.9 s to 1.5-1.6 s on /ar and
    /ar/compare, equal to FCP.
  - `Reveal` armed every scroll-reveal element (opacity 0) on mount,
    including the ones already on screen. When hydration came before the
    first paint, the page's text was hidden at that paint, and the consent
    banner, which appears at hydration, became the LCP element on 13 of 26
    pages (3.0-3.8 s). It also made on-screen text blink out and fade back.
    `Reveal` now arms an element only when the observer's first report puts
    it below the fold.

  `e2e/vitals.spec.ts` holds both, and fails on the previous code.
- [x] **/about failed `definition-list` (a11y 93, both locales).** The
  figures' `<dl>` held a Reveal div around each group's div. The Reveal is
  now the group.
- [x] **Two contrast failures on /compare**, found by the new axe suite:
  the ROI calculator's net figure used the paper shade of `--mint` on the
  espresso card (2.77:1), and its note sat at `opacity-75` (3.58:1).
  `.band-espresso` now re-points `--mint` and `--danger` to on-dark shades,
  as it already did for muted type and the accent, and the note has full
  opacity. tests/tokens.test.ts checks both pairs in both themes.
- [x] **One share card for every page.** Each locale had one Open Graph
  card, so a shared /pricing link unfurled with the home page's headline.
  Every page now has its own 1200×630 card in each language (30 PNGs, its
  title without the brand, under its nav label, with its own URL), named by
  `ogImagePath()` in lib/routes.ts and used for both og:image and
  twitter:image.
  - `scripts/render-brand-assets.mjs` ran again for the first time since
    content/ar.ts started importing `@/lib/consent/copy` (a follow-up in the
    first audit): it now resolves the `@/` alias itself. The icons and the
    Arabic home card came out byte-identical; the English home card changed
    because its hero copy had.
- [x] **The API could be indexed.** `/api/health` answers a GET with JSON.
  `/api/*` now sends `X-Robots-Tag: noindex, nofollow`; robots.txt keeps
  allowing everything, as its comment explains.
- [x] **No accessibility automation** (docs/testing.md). `e2e/a11y.spec.ts`
  runs axe-core (`@axe-core/playwright` 4.13.0, dev only) against WCAG 2.2
  A/AA on all 30 pages, both locales. The step cards' watermark numerals
  (aria-hidden, decorative, WCAG 1.4.3's exemption) are excluded by the class
  pair that draws them.

## Follow-ups

- [follow-up] **Web-font swap shifts /ar/foodics-alternative** (CLS 0.30 in
  2 of 4 production runs, 0.018 in the other two). When the first paint beats
  the text fonts, nine IBM Plex Sans Arabic files (four weights, Arabic and
  Latin subsets, about 210 KB) swap in after it, and the hero subtitle and
  the long disclaimer above the "honest version" section rewrap. Only that
  page has that much body text above its first in-view section; the others
  measure 0.013-0.06. The options trade brand type for stability, so they
  are the owner's call:
  - `display: "optional"` on Plex Arabic: no swap, but a first visit on a
    slow phone reads the body in the system Arabic face.
  - Fewer weights (the first audit's weight-audit follow-up): fewer files,
    fewer late swaps, and a visible change to semibold text.
  - Preloading the regular Arabic file: it starts about 230 ms earlier, which
    the traces show is not enough on a fast first paint.
- [follow-up] **The consent banner is still built at hydration.** With the
  page's own text now visible from the first paint it no longer wins LCP in
  the local runs, but a first visit still paints it late. Rendering it in
  the server HTML (hidden by a boot script when an answer is stored, as the
  theme is) would remove that, and it is a change to
  `components/consent/ConsentManager.tsx`, which is byte-identical across
  the Devya and Moving repos (docs/compliance/consent-design.md).
- [owner] Unchanged from the first audit: Search Console and Bing
  verification, the sitemap submission and Change of Address.

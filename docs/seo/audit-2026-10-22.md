# SEO audit, 2026-10-22

Audit of pos.movingsystems.tech against origin/main 5882080, the day the site
moved from pos.devya.dev (PR #15, which 301s path and query) and named Devya
Solutions as its parent (PR #44). Fixed on branch `feat/seo-audit`.

Each item is marked:

- **[x]**: fixed on this branch. Tests: `tests/seo.test.ts`,
  `tests/jsonld.test.ts`, `tests/proxy.test.ts`, `e2e/seo.spec.ts`.
- **[owner]**: an action only the account owner can take.
- **[infra]**: a server or deploy change (deploy/nginx.conf, scripts/deploy.sh,
  the VPS). The lead makes these.
- **[follow-up]**: left open, with the reason.

## P0: indexing and host

- [owner] **Tell search engines about the move.** Verify the
  `movingsystems.tech` Domain property in Google Search Console (DNS TXT).
  Submit `https://pos.movingsystems.tech/sitemap.xml`. Run Change of Address
  from the pos.devya.dev property, and do the same import in Bing Webmaster.
  Keep the pos.devya.dev 301 and its certificate for at least 12 months, and
  record all of it in README "Deploy".

  - every sitemap `<loc>` starts with `brand.url`;
  - /ar carries its own canonical;
  - `Host: pos.devya.dev` gets a 301 to the same path and query.

  Worth adding with them, from this branch: `/` answers 308, and /favicon.ico
  and /llms.txt answer 200.

## P1

- [x] **/compare had no h1.** `SectionHead` takes `as` ("h1" | "h2") and
  `immediate`. Compare, which only /compare renders, opens with an h1 that
  paints with the server HTML. e2e: one h1 per page, in main, first, for every
  route in both locales.
- [x] **/privacy was indexable but out of the sitemap and the breadcrumbs.**
  It is in `routes`, and the stale "legal pages are noindexed" comment is
  rewritten. `NOINDEX_PATHS` (/terms, /refund) is the one noindex list:
  `buildMetadata` applies it, and a test fails if a page under app/[locale] is
  in neither list.
- [x] **Footer links to `/#how` and `/#roi` landed on nothing.** They now go
  to /how-it-works and /compare#roi. A test resolves every header and footer
  link to a real page, and every fragment to a section that page renders.
- [infra] **HTTP/1.1 only.** Set `listen 443 ssl http2;` on the VPS (nginx
  1.24 predates `http2 on;`), and commit the post-certbot 443 blocks, or a
  setup step that adds http2 to them. Replace `Connection 'upgrade'` with a
  `map $http_upgrade` so `keepalive 32` is used.
- [x] **A carousel image below the fold was preloaded.** ScreenshotCarousel
  preloads only on an opt-in `priority`, and neither caller sets it. e2e: no
  image preload on /ar or /en.
- [x] **Six font preloads (about 190 KB) on every page.** Only Reem Kufi,
  the hero face, keeps its hint (two subsets). IBM Plex Sans Arabic joins the
  Latin faces on `preload: false`. e2e: at most two font preloads.
  - [follow-up] **Weight audit (Plex Arabic 500/600, Plex Mono 500).** Not
    preloaded now, so a weight costs nothing until text uses it. Dropping one
    changes how headings render, and the before/after belongs in Lighthouse
    CI, which xray T6 (#21) owns.
  - [infra] **Re-measure LCP** after HTTP/2 lands. The audit run could not
    resolve the LCP element.

## P2

- [x] **No og:locale:alternate.** `buildMetadata` adds the other locale.
- [x] **Unknown URLs got Next's unbranded 404.** The audit's fix, a
  `[...rest]` catch-all calling notFound(), was built and measured. In Next
  16.4 a notFound() thrown by a dynamic page outside Suspense is answered
  with an empty `__next_error__` shell: no lang, no body, and the layout's
  home canonical and hreflang in the head. The branded page only appears
  once the client renders it.

  So `app/global-not-found.tsx` (`experimental.globalNotFound`) serves every
  URL that matches no page. It is a complete prerendered document with:
  - status 404, noindex, and no canonical or hreflang;
  - Arabic with lang/dir first, then English in its own lang/dir;
  - the mark, and links to both home and pricing pages.

  `dynamicParams = false` on the locale layout sends unknown first segments
  (/nope.php) to it too. `app/[locale]/not-found.tsx` stays for a page that
  calls notFound(), and now has its own title and noindex instead of the home
  page's canonical.

  Checked with `next build` + `next start`: /ar/nope, /en/does-not-exist,
  /ar/a/b, /api/nope, /nope.php and /nope (308 to /ar/nope) all answer 404
  with that page.
- [x] **`/` was a temporary 307.** proxy.ts maps next-intl's 307s to 308,
  which is safe while `localeDetection` stays false. tests/proxy.test.ts
  expects 308 and still keeps the UTM query.
- [x] **Short, keyword-poor titles.** Features, pricing, how-it-works, contact
  and privacy now name their query. Every title is at most 65 characters and
  carries the brand. Breadcrumbs take a page's name from the header and footer
  links, so a long title does not become a long crumb.
- [follow-up] **devya.dev's Organization @id is the www one.** POS points
  `parentOrganization` at `https://devya.dev/#organization`, per the brand
  rule. The fix belongs in devya-solutions: canonical apex, and the @id moved
  to it. tests/jsonld.test.ts pins the parent @id here.
- [x] **Extend the Organization and SoftwareApplication nodes.**
  - A WebSite node (`#website`, ar+en, published by the Organization).
  - The logo is a 512 px PNG ImageObject on this host.
  - `areaServed` is "Egypt".
  - `unitText` is off the AggregateOffer; it stays on each plan's
    UnitPriceSpecification.
  - A screenshot, and `operatingSystem` "Web browser (Android, iPadOS,
    Windows, macOS)".
  - `featureList` no longer claims tiers (see the last follow-up).

  `#software` keeps its @id, which movingsystems.tech links to.
- [infra] **Redirect chains from the old entry points.** On the VPS, make the
  :80 pos.devya.dev block `return 301 https://pos.movingsystems.tech$request_uri`
  (certbot's rewrite adds a hop).
  - [follow-up] devyapos.vercel.app → pos.devya.dev → new host: xray T9 (#24)
    retires or retargets that project.
- [follow-up] **Owned links still use the old host.** docs/social-launch-plan.md
  and docs/compliance/* carry pos.devya.dev; xray T8 (#23) owns docs, and its
  worktree is dirty.
  - [owner] The Instagram bio, the Facebook Page website field and any
    Google Business Profile.

## P3

- [x] **Descriptions over 160 characters** (en home, compare, how-it-works,
  privacy, foodics; ar how-it-works). Every description is 70-160 characters,
  enforced for every page in both locales.
- [x] **/refund and /terms were `noindex, nofollow`.** They are now `noindex,
  follow`. /refund stays linked from the footer, since it only restates the
  trial and cancellation terms the marketing pages promise, and the comment
  says why.
- [x] **SoftwareApplication was emitted sitewide.** Organization and WebSite
  stay sitewide. SoftwareApplication is only on home, /features, /compare and
  /pricing (`APP_PATHS`).
- [x] **The shared FAQPage was on /pricing and /contact.** It is on /pricing
  only.
- [x] **No lastmod, and a non-standard `Host:` line.** Each route carries
  `updated`, the date its copy last changed (typed by hand, never build
  time), and the sitemap emits it. The Host line is gone.
  - Not taken: `disallow: /api/`. Both routes are POST-only and unlinked, and
    robots.ts documents "allow everything" as policy.
- [x] **Header logo label mismatch.** It is named "<product> — Home", which
  starts with the words it shows.
- [x] **8 px carousel dots.** They are 24 px targets with the dot drawn
  inside (e2e checks the size).
- [x] **Footer column titles were h3s.** They are now `<p>`.
  - [follow-up] **The closed consent panel's h2.**
    components/consent/ConsentManager.tsx is kept byte-identical across the
    Devya and Moving repos (docs/compliance/consent-design.md). The change, to
    render the heading only while the panel is open and to show the dialog
    after that render so it keeps its name, has to land in all of them at
    once.
- [x] **The promo poster loaded with the page.** It is a lazy next/image over
  the video until the first frame plays. e2e: no poster request before
  scrolling to it.
- [x] **/favicon.ico 404.** app/favicon.ico is the mark at 16/32/48 px
  (RGBA PNG entries), from scripts/render-favicon.mjs.
- [x] **No /llms.txt.** It is generated from `routes` and the `meta` copy, in
  English and Arabic.
  - [follow-up] **AVIF** (`images.formats`). The sources are already WebP,
    and AVIF is encoded on demand by the server's optimiser, a CPU cost on
    the VPS. Coordinate with ImgBot #7 and xray T6.
- [follow-up] **`site: "pos.devya.dev"` in lead and consent records**
  (app/api/lead, app/api/consent, tests). This is host drift, not SEO. xray T6
  (#21, ARC-F10) owns it.
- [owner] **Organization and ContactPoint email is
  devya.solutions@gmail.com.** The brand rule is hello@<brand>.dev. The
  mailbox has to exist before the markup, footer, security.txt and privacy
  copy change.
- [follow-up] **Visible copy claims loyalty tiers and referrals; the product
  is points only.** The markup and meta no longer say it: the loyalty card
  has a `listName` for `featureList`, and tests fail on tier or referral
  words in JSON-LD or meta. The page copy is unchanged; correct it, then drop
  `listName`:
  - features card title and body ("tiers", "Bronze → … → Platinum", "bring
    friends", "+50% retention"): content/en.ts:213-216, ar.ts:217-220
  - compare row, with `us: true`: en.ts:331, ar.ts:335
